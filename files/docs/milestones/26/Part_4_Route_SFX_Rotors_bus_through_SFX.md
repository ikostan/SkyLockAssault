# Route SFX_Rotors bus through SFX instead of Master

**Labels:** bug, audio  

### Purpose

Make the audio mixer match the volume/mute hierarchy the game already presents to the player. The Audio Settings UI (`_update_ui_interactivity`, `is_sfx_hierarchy_muted`) and `AudioWebBridge` (`_on_change_volume_js`, `_on_toggle_mute_js`) treat **Rotors as a child of SFX**: muting SFX locks the Rotors controls. But `default_bus_layout.tres` sent `SFX_Rotors` straight to **Master**, so muting or lowering SFX had no effect on rotor sounds. `player.gd` plays rotors on `SFX_Rotor_Left` / `SFX_Rotor_Right`, which feed `SFX_Rotors`, so the whole rotor path bypassed SFX.

The bug was found while reviewing #725 against the production code. The routing of the other SFX sub-buses (`SFX_Weapon`, `SFX_Menu` → `SFX`) was already correct.

### Key Changes

- **Bus layout** (`default_bus_layout.tres`)
  - `bus/3/send` (`SFX_Rotors`) changed from `&"Master"` to `&"SFX"`. One line; no other bus changed
- **Runtime routing guard** (`test/gut/test_audio_constants_discoverability.gd`)
  - `test_bus_routing_matches_ui_hierarchy` asserts, against the live `AudioServer`, that every bus sends to its parent in the UI hierarchy: Music and SFX → Master; Weapon, Rotors and Menu → SFX; `SFX_Rotor_Left` and `SFX_Rotor_Right` → `SFX_Rotors`
  - The two rotor playback buses are not in `AudioConstants`, so the test declares them as local constants (`BUS_SFX_ROTOR_LEFT`, `BUS_SFX_ROTOR_RIGHT`)
- **Saved-layout guards** (same file, generated by CodeRabbit)
  - `_layout_bus_index()` helper finds a bus index by name in the serialized `AudioBusLayout`, so inserting a bus doesn't break the tests
  - `test_saved_rotor_output_path_includes_sfx` (parameterized: `SFX_Rotors`, `SFX_Rotor_Left`, `SFX_Rotor_Right`) walks each rotor bus up to Master and asserts every hop passes through `SFX`
  - `test_saved_rotor_send_targets_precede_their_sources` (parameterized: the three rotor buses and `SFX`) asserts each send target has a lower index than its source. Godot only sends to earlier buses; a later target silently falls back to Master
  - `test_saved_rotor_output_path_is_enabled_by_default` asserts no bus on the rotor path starts muted and no bus starts soloed

### Design Decisions

- **Fix the layout, not the UI (Option A).** Two options were considered: send `SFX_Rotors` to `SFX` (A), or take Rotors out of the SFX hierarchy in the UI and the bridge (B). A is a one-line data change that matches what the player already sees; B would change UI behavior and two scripts to keep a routing that was most likely accidental.
- **Valid send target.** `SFX` (index 2) precedes `SFX_Rotors` (index 3), so the new send is legal without reordering buses.
- **Local constants for the rotor playback buses.** `SFX_Rotor_Left` / `SFX_Rotor_Right` are only used by `player.gd` as string literals. Promoting them to `AudioConstants` is outside the scope of a routing bug.
- **Check both the live mixer and the saved file.** The runtime test catches what the engine actually loaded; the saved-layout tests check exactly what ships and are immune to other tests that add or change buses at runtime. The overlap on the rotor hops is intentional and cheap.

### Expected Behavior

| Bus                                  | Sends to (before) | Sends to (after) | Affected by SFX mute/volume |
|--------------------------------------|-------------------|------------------|-----------------------------|
| `Music`                              | Master            | Master           | No                          |
| `SFX`                                | Master            | Master           | (is SFX)                    |
| `SFX_Weapon`                         | SFX               | SFX              | Yes                         |
| `SFX_Menu`                           | SFX               | SFX              | Yes                         |
| `SFX_Rotors`                         | **Master**        | **SFX**          | **Yes** (was: No)           |
| `SFX_Rotor_Left` / `SFX_Rotor_Right` | SFX_Rotors        | SFX_Rotors       | **Yes** (was: No)           |

### Compatibility

- **Audible change:** rotor sounds now follow the SFX mute and volume. A player who had lowered SFX will hear quieter rotors than before.
- No script change. `AudioManager`, the Audio Settings UI and `AudioWebBridge` are untouched; they already assumed this hierarchy.
- Saved audio settings are unaffected: they store per-bus volume/mute, not routing.
- `AudioManager.apply_all_volumes()` overrides each bus's `volume_db` from the saved config at startup, so the layout's own `volume_db` values (e.g. SFX `1.12`) don't change what players hear.
